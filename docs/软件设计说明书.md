## 2. 系统概述

### 2.1 一句话描述

面向中文团队的**敏捷项目管理看板**：以 Scrum 术语建模，把「目标项（要什么）」与「任务项（怎么做）」分开管理，
用迭代驱动交付，用燃尽图看趋势。自建部署、非 SaaS 多租户。

### 2.2 领域模型主线

```
项目 (projects)
 └─ 预期成果看板 (boards.kind = "backlog")   ← 每个项目恰好一个
     └─ 目标项 (goals)                        ← 无负责人、无截止日期，状态由任务派生
 └─ 迭代列表 (boards.kind = "sprint")         ← 可多个
     └─ 任务项 (tasks)                        ← 有负责人、有截止日期、记录工时
         └─ goalTasks                          ← 任务项 ↔ 目标项 多对多
```

外加横向能力：检查列表（目标项的验收条件）、附件、卡片类型（两级词表）、活动日志、燃尽图、用户与权限。

### 2.3 功能范围

| 能力 | 说明 |
| --- | --- |
| 账号与权限 | 自建会话鉴权；全局管理员 + 项目成员（owner/member）两级 |
| 项目管理 | 创建、邀请码加入、邀请/申请审批、成员移除、项目设置、删除级联 |
| 目标项管理 | 名称即录入，类别/客户价值估计后置；三列状态**由任务派生**，不可拖动 |
| 迭代管理 | 未开始/进行中/已结束由日期推导；排入后范围冻结；可移出（连带删任务） |
| 任务项管理 | 提议/执行中/已完成 三态流转，逐级推进，工时随流转录入；三泳道看板 |
| 卡片类型 | 系统级预设（管理员维护，按看板 kind 分）+ 看板自有词汇（复制后可再分化） |
| 检查项/附件 | 目标项验收条件；图片内联、文档下载；20 MB 上限 |
| 进度与燃尽 | 项目进度按目标项计数；迭代工时燃尽 + 发布价值燃尽 |
| 审计 | 活动日志 13 种事件类型 |

### 2.4 用户角色

| 角色 | 判定 | 能做什么 |
| --- | --- | --- |
| 全局管理员 `users.role = admin` | 首个注册者自动成为管理员 | 用户管理、系统级卡片类型预设；**在项目内仍是只读访客**（除非是该项目的成员） |
| 项目 owner `projectMembers.role = owner` | 创建项目者 | 建看板、加目标项、管本看板卡片类型、移除成员、改项目名、删项目 |
| 项目 member `projectMembers.role = member` | 被邀请/申请通过 | 目标项、任务项、检查项、附件的增删改 |
| 未登录 | 无有效会话 | 仅登录/注册页 |

### 3.2 技术选型与理由

| 层 | 选型 | 理由 / 约束 |
| --- | --- | --- |
| 前端框架 | React 18 + TypeScript 5.7（`strict` + `noUnusedLocals` + `noUnusedParameters`） | 类型安全；`tsconfig.json` 的 `include` **同时覆盖 `src` 与 `convex`**，前后端一次 typecheck |
| 构建 | Vite 6 | 产物 `dist/`，文件名带内容哈希 |
| 路由 | **不用路由库** | 视图是有限状态机（见 3.4）；避免为 6 个视图引入路由依赖 |
| 后端 | Convex 1.46 | 云函数 + 文档数据库 + 文件存储一体；**每个函数即一个事务**；客户端 `useQuery` 自动实时订阅 |
| 鉴权 | **自建 token 会话**（非 Convex Auth、不用 `ctx.auth`） | 与 Convex Auth 的账号体系解耦，便于两个独立 deployment 各自拥有账号 |
| 密码哈希 | **纯 TypeScript 的 PBKDF2-HMAC-SHA256**（`convex/lib/password.ts`） | Convex 的 V8 isolate 不保证有 `crypto.subtle`；且 `"use node"` 模块不能被**同时导出 query/mutation** 的文件 import。刻意实现，**不要换成原生 crypto** |
| 部署（前端） | Cloudflare Pages | 静态托管 + `_redirects` 做 SPA 回退 |
| 部署（后端） | 两个独立 Convex deployment | dev 用于试验，prod 承接真实数据（**prod 数据不可删除**，见《维护手册》） |

### 3.3 双后端与运行时切换

这是本项目最独特的设计，**改动前务必理解**。

- `src/backend.ts` 定义 `BACKENDS = { prod, dev }`，每项含 `label` / `host` / `url`；
  `DEFAULT_ENV = "prod"`，可被 `VITE_CONVEX_URL_PROD` / `VITE_CONVEX_URL_DEV` 覆盖。
- `Root`（`src/main.tsx` 内）持有当前 env 状态：
  - `clientFor(env)` 按 env 返回缓存于**模块级 Map** 的 `ConvexReactClient`。
    **client 不能建在组件 effect 里** —— React StrictMode 会双挂载 effect，而每个 client 握着一条 websocket；
    按 env 缓存后，来回切换最多只存在 2 个 client。
  - 切换时先 `writeToken(null)`（**会话只存在于签发它的那个 deployment**，不清会立刻 401），
    再 `writeEnv` + `setEnv`，并用 `<App key={env}>` 强制重挂载，重置所有视图状态。
- 切换入口**只放在登录页**（`AuthPage.tsx` 的「后端数据」选择器），因为两个库账号互不相通，
  换后端必然要重新登录；选择器下方显示当前 deployment 主机名，避免"不知道自己在哪个库"。
- ⚠️ `.env.local` 里的 `VITE_CONVEX_URL` / `VITE_CONVEX_SITE_URL` **客户端已不再读取**
  （仅 `scripts/project-snapshot.mjs` 拿它做 sanity gate）。**改它不会切换后端**。

### 3.4 前端架构

**视图状态机**（`src/App.tsx`，无路由库）：

```ts
type View =
  | { kind: "projects" }
  | { kind: "project"; id: Id<"projects"> }
  | { kind: "board"; id: Id<"boards">; projectId: Id<"projects"> }
  | { kind: "admin" }
  | { kind: "presets" }
  | { kind: "account" };
```

- 顶栏（桌面）与底部 `.tabbar`（≤760px）渲染同一组目的地；管理员多出「卡片类型」「用户管理」。
- 会话失效（`me === null`）→ 清 token 并退回登录页；`booting` 期间显示「加载中…」。
- `BoardPage` 需要 `isProjectOwner`，由 `App` 从 `listMyProjects` **首页**推导；
  超出首页范围时降级为只读（已知取舍，见 §9.2）。

**数据获取**：一律 `useQuery(api.<module>.<fn>, args | "skip")`。
不引入全局 store —— Convex 的实时订阅本身即是缓存与失效机制。视图内局部状态用 `useState`。

**错误处理约定（硬性）**：

1. 绝不把后端错误原文渲染给用户，一律 `describeError(err)`（`src/lib/ui.ts`）。
2. 新增后端错误码**必须**登记到 `ERROR_MESSAGES`（当前 49 条，码 → 中文）。
3. 每个 mutation 都要 try/catch 并 toast（**当前仍有若干处遗漏**，见 §9.2）。

**样式**：单一 `src/styles.css`（1934 行），`:root` 定义 token，深色模式用**唯一一个**
`@media (prefers-color-scheme: dark)` 块重声明同名变量（无 `data-theme`、无 JS 切换）；
移动优先，断点 760 / 720 / 420 px。文件结构是**追加式**：新规则加到文件末尾并写注释段。

### 3.5 后端架构

- 函数类型：`query`（只读、可订阅）、`mutation`（事务写）、`internalMutation`（不对外暴露，本仓库仅在一次性维护时临时使用）。
- **每个函数收 `token: v.optional(v.string())`**，通过 `convex/lib/auth.ts` 的守卫解析会话。
- `returns` 校验器**全部写全**：改返回值必须同步改校验器与 `src/components/types.ts`。
- **无外键**：删除父实体必须手工级联（`deleteProject` 是范例，见 7.6）。
- 索引是性能前提：**新增查询前先确认有可用索引**。
- 共享常量放在 `convex/lib/constants.ts`（`src/` 直接 import，保证前后端校验一致）。
  `convex/lib/*` **必须保持前后端无关**，不得引入服务端专属依赖。

## 4. 数据表设计

完整定义见 `convex/schema.ts`。**索引是查询前提，改表前先读本节的索引列。**

### 4.1 通用约定

| 约定 | 说明 |
| --- | --- |
| 主键 `_id` | Convex 自动生成；客户端类型保留 `Id<"table">` 品牌 |
| `_creationTime` | Convex 自动写入，用于同 `position` 时的稳定排序兜底 |
| `position` | 手工维护的排序字段；查询按 `position` 升序、`_creationTime` 兜底 |
| `archived` | 软删除标记（`boards` / `projects`）；查询一律过滤 |
| 时间 | 一律 `number`（epoch 毫秒） |
| 无外键 | 引用完整性由**业务代码**保证；删除必须手工级联 |
| 可选字段 | `v.optional(...)`；`undefined` 与 `null` 语义不同（见 7.3） |

### 4.7 实体关系

```
users ──1:N── sessions
  │
  ├──1:N── projects (ownerId) ──1:N── boards ──┬─1:N── columns ──1:N── goals
  │                                          └─1:N── labels(scope=project)
  ├──1:N── projectMembers (userId)                  │
  ├──1:N── joinRequests (userId)                    │
  └──1:N── activityLog (actorId)                    │
                                                    │
projects ──1:N── goals ──┬──1:N── checklistItems    │
                         ├──1:N── attachments       │
                         └──N:M── tasks (via goalTasks)
                                     │
projects ──1:N── tasks ──────────────┘   (tasks.boardId 指向 sprint 板)
projects ──1:N── burndown
labels(scope=system, 带 kind)  ──播种──▶  labels(scope=project)
```

## 5. 接口设计

### 5.1 调用约定

| 项 | 约定 |
| --- | --- |
| 调用方式 | 前端 `useQuery(api.mod.fn, args)` / `useMutation(api.mod.fn)`；脚本走 HTTP `POST /api/query` \| `/api/mutation` |
| 鉴权 | 每个函数都有 `token: v.optional(v.string())`；缺失/过期 → `UNAUTHENTICATED` |
| 返回值 | `returns` 校验器**全部写全**；改返回结构必须同步改校验器与 `src/components/types.ts` |
| 错误 | `throw new Error("CODE")`，码 → 中文映射在 `src/lib/ui.ts`（当前 49 条） |
| 实时性 | `query` 自动订阅；mutation 提交后相关 query 自动重算 |

> ⚠️ **生产环境会脱敏错误信息**：`throw new Error("CODE")` 的错误码在 prod 上**透不出来**
> （客户端只收到 `Server Error`）。正确修法是改用 `ConvexError`
> （`convex/` 内约 128 处待迁移）。当前 `describeError` 已加兜底，见 §9.2。

## 7. 核心业务流程与不变量

> 本节是**最需要精确**的部分。改动相关代码前请完整阅读。

### 7.1 目标项状态派生（`goals.ts: syncGoalStatus` / `isGoalComplete`）

```
已完成  ⇐ 至少 1 个任务 且 全部任务 done
处理中  ⇐ 未全部完成，但 sprintId 有值（已排入迭代）
待处理  ⇐ 未排入迭代
```

- **空任务集不算完成**（否则新建目标项会立刻"已完成"）。这是**刻意**的，不要"修复"。
- **手工新增只能落在「待处理」**：服务端拒绝建到 处理中/已完成（`NEW_GOAL_MUST_BE_PENDING`），
  客户端也只在「待处理」列渲染新增框。否则会写入与派生规则立刻矛盾的列状态（处理中却没有 `sprintId`）。
- 状态列**只在服务端派生写入**，客户端不允许把目标项拖到别的列（本项目**没有任何拖拽实现**）。
- 任何影响任务的改动后都会重算目标项状态并刷新燃尽图。

### 7.2 任务状态流转（`goals.ts: setTaskStatus`）

| 目标状态 | 服务端行为 |
| --- | --- |
| → `in_progress` | 打 `startDate`（若空）、写入 `estimatedHours`、清空 `actualCompletedAt` / `actualHours` |
| → `done` | 打 `startDate`（若空）、打 `actualCompletedAt = now`、写入 `actualHours` |
| → `proposed` | **清空全部四个字段**（重新开始计时，数字保持诚实） |

- 客户端强制**逐级推进**：不能 `proposed → done` 一步到位；`done` 可「撤回」。
- 进入 `in_progress` 强制要求预计工时；进入 `done` 强制要求耗费工时（>0）。
- 返回 `{ goalsCompleted }` 供 UI 提示。

### 7.3 迭代与范围冻结

- 每个项目**恰好一个**未归档 backlog；`createProject` 自动建 backlog 及三列。
- `sprintStatus` **由日期推导**（`deriveSprintStatus`）：开始日当天仍为「未开始」，次日起「进行中」，结束后「已结束」。
- `endDate` 可省略 → `startDate + sprintLengthDays * DAY_MS`；`endDate <= startDate` → `INVALID_SPRINT_RANGE`。
- **`planGoalToSprint` 只允许「未开始」的迭代** —— 迭代一旦开始，范围冻结（`SPRINT_NOT_PLANNED`）。
- **移出迭代**（`sprintId: undefined`）**连带删除该目标项的任务**（任务属于迭代，会变孤儿）；
  但**检查项与附件跟随目标项，保留不动**。
- 迭代名称留空 → 服务端自动命名 `迭代 N`（N = 现有最大编号 + 1）。

### 7.4 卡片类型：两级词表与播种规则

```
系统级预设 labels(scope=system, 带 kind)
        │  建板时按 kind 播种
        ▼
看板自有 labels(scope=project, 带 boardId)
        │  同项目、同 kind 的看板之间互相继承
        ▼
卡片只存 labelId 引用
```

`seedDefaultLabels` 的决策顺序（**改这里务必保持**）：

1. 该看板已有类别 → 直接返回（幂等）。
2. 找**同项目、同 `kind`** 的兄弟看板 → 有则**复制它的词表**
   （例：第二个迭代继承第一个迭代的任务类别）。
3. 否则用**该 `kind` 的系统预设**。
4. 系统预设为空 → 用内置 `DEFAULT_LABELS[kind]` 兜底（保证看板不会"一个类别都没有"）。

> ⚠️ **绝不能跨 kind 复制**。曾经用 `find(b => b._id !== board._id)` 匹配**任意**兄弟看板，
> 于是新建迭代会继承「预期成果看板」的类别，导致任务项无论怎么选都只能是目标项的类别。
> 系统预设本身就是按 kind 分的两套（例：backlog `约束/功能/性能`、sprint `文档/测试/程序/美术/策划`）。

其它规则：

- **目标项与任务项的词表不可混用**：`getBoard` 同时返回 `labels`（当前看板）与 `goalLabels`（预期成果看板）。
- 管理员改系统预设**不会**改写已有卡片（预设只在建板时复制一次）。
- `normalizeColor` 只接受 `#rgb` / `#rrggbb`，其它回退 `#64748b`。
- 删除保护：有卡片引用 → `LABEL_IN_USE`；删最后一个 → `CANNOT_DELETE_LAST_LABEL`。

### 7.5 进度与燃尽图

- 项目进度**只按目标项计数**（不是任务项）：`percent = round(completed / total * 100)`，分母 0 时为 0。
- 两种燃尽图共用 `burndown` 表，靠 `scope` 区分（见 4.6）。
- `baseline` = 迭代开始时的工时 / 立项时的点数；`ideal` 为直线。
- 写入按 key upsert。
- `scripts/project-snapshot.mjs` **刻意不备份 `burndown`**（派生数据）。

### 7.6 `deleteProject` 的完整级联（12 张表）

无外键，因此删除必须手工级联。当前实现覆盖：

```
按 projectId：goals→goalTasks / tasks / attachments(+storage) / checklistItems /
              burndown(release，不带 boardId！) / projectMembers / joinRequests(全部状态) /
              activityLog / projects
按 boardId  ：columns / goals / burndown(sprint) / **labels** / boards
```

三个**曾经漏掉**、现已修复的点（改动时勿回退）：

1. **项目自己的 `labels`** —— 漏删会留下悬空 `boardId`，且事后**无法用 `deleteLabel` 清理**
   （它的 owner 守卫要求 board 仍存在 → `BOARD_NOT_FOUND`）。
2. **非 `pending` 的 `joinRequests`** —— 原先只删 `status="pending"`，已批准/已拒绝的变孤儿。
3. **`scope="release"` 的 `burndown`** —— 这些行**不带 `boardId`**，按 board 的循环永远匹配不到。

### 7.7 检查项与附件

- 检查项是**目标项的验收条件**，与任务表完全独立；可带历史遗留的可选负责人/检查日期，但 **UI 只保留文本**。
- 附件上限 **20 MB**；`isImage` 服务端判定；图片内联、文档走一次性签名 URL 下载。
- `ctx.storage.delete` best-effort。

## 8. 权限模型

**鉴权是自建的**（每个函数收 `token`），守卫集中在 `convex/lib/auth.ts`：

| 守卫 | 语义 | 失败错误码 |
| --- | --- | --- |
| `getUserByToken` | 解析票据；无效/过期返回 null | — |
| `requireUser` | 有效且未停用的账号 | `UNAUTHENTICATED` / `SUSPENDED` |
| `requireAdmin` | 全局管理员 | `FORBIDDEN` |
| `requireProjectMember` | **写权限的唯一依据**：必须是项目成员 | `PROJECT_NOT_FOUND` / `NOT_A_PROJECT_MEMBER` |
| `requireBoardMember` | 由看板反查项目并要求成员 | `BOARD_NOT_FOUND` |
| `requireProjectOwnerOf` | 项目 owner 专属（建看板、加目标项） | `PROJECT_OWNER_ONLY` |
| `requireLabelEditor` | 系统预设要 admin；项目标签要 owner | `FORBIDDEN` / `PROJECT_OWNER_ONLY` |
| `requireColumnOfBoard` | 列必须属于该看板 | `COLUMN_NOT_FOUND` |

**关键设计（易踩坑）：全局管理员在项目内是「只读访客」。**
管理员可查看任何项目，但**写操作以项目成员身份为准**，所以管理员不会悄悄改别人的看板。

**已知不一致（UI 比服务端更严）**：`getProject` 把 `pendingRequests` 返回给**所有成员**；
`decideJoinRequest` / `inviteUser` / `updateProject` 服务端也只要求「是成员」，而 UI 只对 owner 显示入口。
服务端并未强制 owner。

## 9. 设计约束与取舍

### 9.1 刻意的设计（不要"顺手优化"）

| 设计 | 原因 |
| --- | --- |
| 无路由库，用视图状态机 | 视图有限（6 个），避免引入依赖 |
| 自建会话而非 Convex Auth | 两个 deployment 账号独立，与 Convex Auth 体系解耦 |
| 纯 TS PBKDF2 而非原生 crypto | V8 isolate 不保证 `crypto.subtle`；`"use node"` 与 query/mutation 不能共存于同一文件 |
| ErrorBoundary 包在 Provider 外层 | 任何 query 抛错都不白屏 |
| Convex client 缓存在模块级 Map | StrictMode 双挂载 effect，client 握着 websocket，不能每次重建 |
| 空任务集不算完成 | 否则新建目标项立刻"已完成" |
| 目标项状态完全派生、不可拖动 | 避免列状态与 `sprintId` 矛盾 |
| 卡片类别只画颜色方块 | 看板保持可扫读；名称在 `title` 与详情里 |
| 新建卡片不问类别 | 先记录再分类，降低录入摩擦 |
| 描述字段已弃用但保留列 | 不做破坏性迁移、不丢历史数据（见 9.2） |
| `labels` 一份数据两种 scope | 系统预设与看板自有词表同构，播种/复制逻辑统一 |

### 9.2 已知问题与技术债

**后端**

- ⚠️ **生产环境脱敏错误信息**：约 128 处 `throw new Error("CODE")` 在 prod 上不透出错误码，
  导致 `ERROR_MESSAGES` 映射失效。正确修法：改用 `ConvexError` 并让 `describeError` 优先读 `err.data`。
  当前 `describeError` 已剥离 `[CONVEX …]` / `[Request ID: …]` 外壳并有兜底文案。
- `progress.ts` 的 `effortStats` / `listTasks` 的 **returns 校验器**里 `labelId` 仍为 `v.optional` —— 这是**对的**
  （历史数据可能无类别），不要跟着 args 一起收紧。

**数据**

- 曾经"已弃用但未删除"的三列 —— `goals.description`、`checklistItems.assigneeId`、
  `checklistItems.checkDate` —— 已于 2026-10-13 按《维护手册》第 7 节流程**彻底删除**（含数据）。
- `.import-tmp.json` 含明文 session token（已 gitignore，建议删除）。
- `snapshots/latest.json` 里是**绝对路径** `/Users/alex/workspace/kanban/...`，与当前 checkout 不一致。
- `scripts/reset-data.sh` 早先的表清单曾与 schema 漂移（已修正为 15 张表）。

**前端**

- **没有任何拖拽实现**，排序与流转全靠按钮；但 `styles.css` 里 `.column.drag-over`、`.drop-line` 是死 CSS。
- `styles.css` 有一段**没有选择器的孤立声明块**（约 6 条声明），浏览器静默丢弃，`vite build` 会告警。
- `ProjectPage.submitBoard` **不传 `description`** → 新建迭代弹窗的「描述（可选）」是**死输入框**。
- 多处 mutation 缺 try/catch（排序按钮、移出迭代、检查项 toggle/remove）→ 未处理的 rejection。
- `BoardPage` 早退 `if (!data) return "加载中…"` → 加载与错误不区分。
- 直接展示了错误码字符串 `"INVALID_CUSTOMER_VALUE"` 而非走 `describeError`。
- `ProjectsPage` 的 `listMyJoinRequests` 未加 `"skip"` 守卫。
- `listAllProjects` 的 `role` 是按 `ownerId` 推的，不代表调用者真实成员关系。
- `overdue` 在渲染时用 `Date.now()` 计算 → 页面常开不会自动翻转。
- `TaskCard` 有两段重复 JSDoc；`hours()` 与 `hrs()` 是重复实现。
- 品牌不一致：应用内顶栏（`App.tsx`）仍写 "My KanBan"，登录页与页面标题是「敏捷项目管理看板」。
